# 进阶说明

[pi-language-tutor](../README.zh-CN.md) 的更细行为。日常使用请先看 [README](../README.zh-CN.md)。

## 哪些消息会被检查

为了省 token、少打扰，以下消息**不会**触发检查：

- 斜杠 / 感叹号命令
- 过短的消息
- 以代码或路径为主的消息
- `/lang check off`（或 `/lang off`）期间的所有输入

CJK 文本按**字符数**计算（而不是按空格分词），所以用母语写的一整句仍然会进入写作辅导。检查只在交互式 TUI 里运行；就算检查失败，也不会影响你的会话。

## Writing check 与 Writing tutor

每条消息只发一次 LLM 调用，由模型选择模式：

| Prompt 语言              | 面板              | 做什么                                         |
| ------------------------ | ----------------- | ---------------------------------------------- |
| 学习语言                 | `✏ Writing check` | 拼写、语法、表达 + 母语讲解 + 整句更地道的写法 |
| 母语（或其他非学习语言） | `✏ Writing tutor` | 学习语言的整句表达、关键词汇和语法点           |

两者互补，**绝不会**在同一条消息上同时出现。

如果你本来就习惯用母语写 prompt、觉得辅导面板太吵，可以关掉：

```text
/lang tutor off
```

之后母语消息不再显示任何面板；学习语言上的写作检查照常工作。

## 记忆卡片

Writing tutor 教过的单词会自动保存，并按单词去重。运行 `/flashcards` 可以打开复习窗口，浏览整个词库，或开始复习已经到期的卡片。

- 查看答案后，按 Again / Hard / Good / Easy 评价记忆情况。
- Again 和 Hard 会让卡片留在本轮中；Good 和 Easy 会让它毕业，等到下一个到期日再出现。
- 调度通过 `ts-fsrs` 使用 FSRS，并关闭分钟级学习步骤，因此每次评分都会直接进入以天为单位的间隔。
- 每天引入的新卡和每轮复习数量都有上限，两者都可以在复习窗口中修改。
- 卡片可以编辑或删除。保存采用原子写入；窗口打开期间捕获的新词会被合并，不会遭到覆盖。

卡片保存在 `~/.pi/agent/flashcards.json`。`~/.pi/agent/flashcards-settings.json` 保存 `newPerDay`、`sessionLimit` 和 `requestRetention`（FSRS 目标记忆保留率；需要直接编辑文件，界面中不开放）。

## 双语卡片

- 段落按**原文在上、译文在下**排列，和沉浸式翻译一个风格。
- 短代码块（≤5 行）原样保留；更长的用 `[code block ↑ N lines]` 占位（完整代码仍在上方原文里）。
- 自动模式（`/lang auto on`）会跳过中间的工具调用叙述和少于约 15 个词的回复。
- 开启自动翻译时，状态栏显示 `🌐 auto`。

## 自定义 provider

在 **pi 0.81+** 上，写作检查和翻译直接走组合 provider 的 `streamSimple`——与主会话完全相同的分发路径——因此无论 provider 是以配置形式注册（如 Cursor 的 `cursor-sdk`）还是以原生 `Provider` 对象注册，都能正常工作。

在 **pi 0.80** 上则回落到 pi-ai 的 `completeSimple`，那里的全局 API registry 本就覆盖自定义 provider。

## 上下文模式

```text
/lang context on     # 翻译携带完整会话（默认关闭）
/lang check context  # 写作检查与辅导能看到会话历史
```

### 翻译上下文为何默认关闭

默认情况下翻译只能看到被翻译的那条消息，代词指代、项目名、会话里约定的术语都可能译得很泛。上下文模式会从主会话 **fork** 出翻译请求：完整复用主会话上一次 LLM 请求的前缀（相同的工具定义、系统提示词和消息历史）。服务商可以把这段前缀从 prompt cache 里取出，你只需付**缓存读取**的价格（Anthropic 约为正常输入价的 10%）加上翻译本身的开销。

### 两点注意

1. **只有使用会话模型时才划算。** 用 `/lang model` 指定了别的模型就无法命中主会话的缓存，每次翻译都会按全价重新计费整段历史。这也会改变数据的去向：发给该服务商的是整段对话，而不只是被翻译的文本。扩展会在启动和切换模型时对这种组合发出提醒；运行 `/lang model default` 即可解决。
2. **会话第一轮 agent 对话之前**还没有可复用的请求，此时翻译会静默回退到无上下文模式。

### 检查上下文刻意独立

`/lang check context` 与 `/lang context` 互不影响。检查在你发出的每条消息上都会触发，开启后每次检查都要付一次缓存读取。只有当检查总把项目术语误报成错误时才值得打开——带上下文的检查能认出会话里约定的名称和造词，辅导教你表达时也会优先用它们。
